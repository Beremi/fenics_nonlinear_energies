# Clean revision-publication campaign finalization

This workflow creates the 14 source files consumed by the revision evidence
tables without promoting any current pilot output. The producer boundary is
[`finalize_revision_publication_campaign.py`](../../experiments/analysis/finalize_revision_publication_campaign.py).
It does not submit scheduler jobs. On Karolina, its `execute` command is run
inside an allocation that has already passed the separate human-release gate.

## Non-negotiable contract

One Git commit is the experiment commit. It must contain the final producers,
protocols, analysis contract, and finalizer, and the worktree must be clean
immediately before and after every managed command. A later release HEAD is
allowed only when it is a clean descendant and every bound producer and
configuration file remains byte-identical.

The current `paper_revision_2026_07_10/pilots` directory is not an input to
this workflow. A pilot or dirty declaration, a pilot override, an already
decorated payload, a stale producer, an unexplained staging input, or a changed
raw output stops finalization. Conservative raw producers that write
`publication_evidence: false` are accepted only when the raw payload itself
contains no pilot/dirty declaration and the file was generated by the managed
clean execution receipt. The untouched raw file remains in
`_publication_staging`; the table-facing publication copy is a separate file.

Route finalization is outcome-independent. A complete clean route campaign may
end as `predictive_selector_admissible` or, when a frozen fit/design gate fails,
as `finite_empirical_map_only`. Both require the exact 96 active rows, six
structural censors, 74 training rows, 22 holdout rows, and endpoint-correct
Tier-B evidence. The negative branch is publication evidence for the finite
descriptive map only: the finalizer rejects coefficients, predictions,
rankings, recommendations, and post-fit crossover objects on that branch. A
consistent synthetic-factor diagnostic failure is retained and reported but
does not select either terminal.

## Ordered execution

1. Commit and review the implementation. Confirm that `git status
   --porcelain=v1 --untracked-files=all` is empty. Do not change producers after
   this point.

2. Create a fresh ignored campaign root and generate the canonical source plan:

   ```bash
   ROOT=artifacts/reproduction/paper_revision_publication_clean_v1
   ./.venv/bin/python experiments/analysis/finalize_revision_publication_campaign.py \
     init-plan --output "$ROOT/execution_plan.json"
   ./.venv/bin/python experiments/analysis/finalize_revision_publication_campaign.py \
     validate-plan --plan "$ROOT/execution_plan.json"
   ```

   The generated plan contains all 14 exact source paths and producers. It also
   names six prerequisites that cannot safely be inferred: clean P1/P2/P4
   Plasticity3D endpoint states, the strict Tier-B endpoint analysis, the
   reviewed Karolina campaign master archive, and the workstation archive.

3. Produce each prerequisite at the same commit with a
   `dependency_preparation` plan. A dependency command has no table-facing
   source key and must declare every output explicitly. The minimal shape is:

   ```json
   {
     "schema_id": "fenics-nonlinear-energies.revision-publication-execution-plan",
     "schema_version": 1,
     "plan_kind": "dependency_preparation",
     "campaign_id": "paper_revision_publication_clean_v1",
     "experiment_commit": "<40-digit clean commit>",
     "commands": [
       {
         "id": "prepare_p1_l1_state",
         "role": "preparation",
         "source_keys": [],
         "producer": "<canonical tracked producer path>",
         "argv": ["{python}", "<producer>", "<arguments>"],
         "environment": {},
         "configuration_files": ["<canonical tracked protocol/config path>"],
         "input_files": [],
         "expected_artifacts": ["EXP-DISC-001/clean_inputs/p1_l1_state.npz"]
       }
     ]
   }
   ```

   Execute it with the same evidence root. The receipt will be written to
   `_publication_receipts/prepare_p1_l1_state.json`, exactly where the canonical
   source plan expects it:

   ```bash
   ./.venv/bin/python experiments/analysis/finalize_revision_publication_campaign.py \
     execute --plan "$ROOT/dependency_plan.json" \
     --command-id prepare_p1_l1_state --evidence-root "$ROOT"
   ```

   Repeat for the remaining five named prerequisites. A staging dependency is
   accepted only if its receipt records the same clean commit and exact output
   SHA-256. Therefore copying an old state or manifest into the expected path
   does not satisfy the contract.

4. Stage the completed workstation campaign and copied-back Karolina route
   archive with the tracked offline dependency producer. The endpoint and STOP
   arguments are relative to the copied-back Karolina archive, so verified
   copy-back evidence remains relocatable:

   ```bash
   HEAD=<full-40-digit-experiment-commit>
   ./.venv/bin/python experiments/analysis/stage_route_publication_dependencies.py plan \
     --expected-commit "$HEAD" \
     --workstation-source /path/to/completed/workstation/archive \
     --karolina-source /path/to/copied-back/karolina/archive \
     --endpoint-relative path/to/tier_b_endpoint_analysis.json \
     --stopping-relative path/to/stopping_adjudication.json \
     --output "$ROOT/route_dependency_plan.json"

   for COMMAND_ID in \
     prepare_workstation_archive \
     prepare_route_campaign_master \
     prepare_route_stopping_adjudication \
     prepare_tier_b_endpoint_analysis
   do
     ./.venv/bin/python experiments/analysis/finalize_revision_publication_campaign.py \
       execute --plan "$ROOT/route_dependency_plan.json" \
       --command-id "$COMMAND_ID" --evidence-root "$ROOT"
   done
   ```

   This path performs no scheduler or remote operation. It applies the route
   analyzer's workstation, Karolina, complete-map, factor-diagnostic, and
   Tier-B endpoint and detached-STOP gates before and after copying. The
   dependency plan freezes every regular source file by relative path and
   SHA-256; links, changed source trees, incomplete workstation closure, and
   mixed commits are rejected. The managed receipts, their plan, their logs,
   and every planned output are revalidated when a source command consumes an
   attested input. All four route receipts must share the canonical
   `paper_revision_route_dependencies_v1` plan and tracked staging producer;
   alternate preparation commands or receipt mappings are rejected.

   The Karolina route master must recursively bind every tranche manifest,
   submitted-job ledger, human release authorization, and reviewed
   authorization artifact. The endpoint must admit all 30 paired blocks. The
   only permitted non-attempts are the two rank-specific Tier-B P4 colored-SFD
   rows and the six corresponding fixed-state map slots, all with reason
   `prespecified_not_attempted_memory_risk_no_threshold_claim` and no exposed
   or imputed time.

5. Execute the 14 source commands. Independent commands may run in parallel,
   but each command ID has one exclusive receipt and raw-output set. Never run
   two copies of the same command ID. For example:

   ```bash
   ./.venv/bin/python experiments/analysis/finalize_revision_publication_campaign.py \
     execute --plan "$ROOT/execution_plan.json" \
     --command-id val_plaplace --evidence-root "$ROOT"
   ```

   Run every ID printed in `execution_plan.json`. `execute` refuses preexisting
   raw targets, uses argv directly without a shell, records stdout/stderr,
   captures package and selected runtime environment versions, and binds the
   producer, configuration, input, and raw-output hashes.

6. After all receipts are complete, finalize once:

   ```bash
   ./.venv/bin/python experiments/analysis/finalize_revision_publication_campaign.py \
     finalize --plan "$ROOT/execution_plan.json" --evidence-root "$ROOT"
   ```

   Finalization refuses existing table-facing outputs. It validates the strict
   publication run records for EXP-MC-001 and EXP-DIST-001, decorates each raw
   source with a versioned `source_schema` and `publication_provenance`, and
   writes six admission-compatible companion manifests. The route companion
   additionally binds the Tier-B endpoint result and the route master,
   tranche, ledger, authorization, and analyzer-input inventory.

7. Verify before and after any copy or archival operation:

   ```bash
   ./.venv/bin/python experiments/analysis/finalize_revision_publication_campaign.py \
     verify --evidence-root "$ROOT"
   ```

8. Only after producer verification succeeds, run the independent admission
   boundary and table generator:

   ```bash
   ./.venv/bin/python paper/scripts/admit_revision_publication_evidence.py admit \
     --evidence-root "$ROOT" \
     --manifest-out "$ROOT/publication/publication_evidence_manifest.json"
   make -C paper tables \
     REVISION_EVIDENCE_ROOT="../$ROOT" \
     REVISION_EVIDENCE_CLASS=publication \
     REVISION_EVIDENCE_MANIFEST="../$ROOT/publication/publication_evidence_manifest.json"
   make -C paper submission-check
   ```

The producer finalization manifest and the independent admission manifest serve
different purposes. The former proves how clean raw files became canonical
sources; the latter independently rechecks scientific gates and decides whether
those sources may enter publication tables. Neither file should be edited by
hand.
