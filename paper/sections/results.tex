\subsection{Globalization Method Comparison}
\label{sec:num-globalization}

\Cref{tab:globalization-method-compare} isolates the nonlinear globalization
choice on four benchmark configurations using the same element assembly path
and fixed preconditioner family within each problem. The scalar cases use
level-10 meshes obtained by one additional uniform refinement of the level-9
inputs. The $p$-Laplace globalization row is a separate unit-load
($f=-1$) stress test on the same L-shaped hierarchy, so its energies are not
compared with the $f=-10$ benchmark and scaling rows in
\Cref{sec:bench-plaplace,sec:num-plaplace}. For $p$-Laplace, the comparison
uses 32 MPI ranks with a 30 s wall-time cap. For Ginzburg--Landau, the reported
comparison uses 16 MPI ranks with a 120 s wall-time cap. For hyperelasticity,
the comparison uses the first eight load steps of the level-4 rank-local
assembly path on 32 MPI ranks with a 270 s cap. The Plasticity3D comparison
uses the $P_2(L_1)$ endpoint surrogate at
$\lambda_{\mathrm{sr}}=1.55$ on 32 MPI ranks with a 180 s cap. Timed-out
configurations are retained in the comparison; the table uses solver-reported
solve time for completed solves and elapsed wall time for timed-out cases.
In the line-search configurations the trust-region machinery is disabled; in
particular, the hyperelasticity line-search baseline uses GMRES rather than the
STCG trust-region subproblem solver. For the Plasticity3D configuration, all
methods are judged against the stricter
$\|\nabla \mathcal{F}\|_2 < 10^{-4}$ endpoint criterion.

In the clean $p$-Laplace unit-load row, Newton with Armijo line search completes
with the lowest reported solve time. Ginzburg--Landau separates the policies
more sharply: the same line-search-only policy times out under the
fixed cap, while both trust-region variants converge to the same reported
energy. For the hyperelasticity excerpt all three policies complete, but
Steihaug trust-region globalization without the line-search subproblem safeguard
has the largest trust-region rejection count and a larger solve time than the
hybrid policy, whereas line-search-only Newton is slowest. The hybrid policy
keeps the trust-region safeguard while reducing both nonlinear iterations and
solver time relative to line-search-only Newton. The Plasticity3D endpoint gives
the opposite conclusion from the easy scalar case: at the stricter
$\|\nabla \mathcal{F}\|_2 < 10^{-4}$ criterion, line-search-only Newton reaches
the iteration cap, whereas both trust-region policies converge. The capped row
matches the displayed energy but remains above the gradient target, as reported
by the gradient-to-target column in
\Cref{tab:globalization-method-compare}. The hybrid variant is the fastest of
the two trust-region configurations and also uses fewer Krylov iterations.
Together, these comparisons support a problem-dependent policy choice rather
than a universal preference for any single globalization strategy.

\subsection{Derivative-Route Comparison}

\Cref{tab:derivative-route-compare} isolates the cost of the second-order

the first level-4 load step and intentionally use the replicated element path
for both routes, because the rank-local hyperelasticity configuration does not use
colored sparse recovery. This makes the case a derivative-route comparison rather than a
scaling claim. The Plasticity3D cases use the same

rank-local HVPs having nearly the same measured Hessian-evaluation cost as element

reconstruction.

nonlinear stop requires both relative correction below \num{0.002} and a

\subsection{Topology Optimization}
\label{sec:num-topology}

The reduced design problem and objective history are defined in
\Cref{sec:bench-topology}, with mechanics subproblem \eqref{eq:topology-mechanics}
and reduced objective \eqref{eq:topology-reduced-objective}.
The numerical question here is distributed outer-loop stability: the mechanics
solve and the design update must remain synchronized under continuation in $p$
and move-regularized updates. Because the outer-loop work can vary with the
continuation schedule, the timing evidence here should be read as end-to-end
timing under adaptive stopping rather than strong scaling at a fixed
computational workload.

\subsection{Synthesis of the Computational Evidence}
\label{sec:num-synthesis}

The results above provide the evidence blocks used in
\Cref{sec:discussion}. The globalization tests separate problem-dependent
nonlinear policies; the derivative-route comparisons isolate cost under fixed
terminal observables; the distribution, PMG, and partitioning studies expose
solver-policy and sparse-ownership effects; and the topology study closes with
an end-to-end design-and-mechanics loop plus a controlled rank-consistency
check. Read together, these measurements support interpretation at the level of
a coupled nonlinear FEM method, rather than a universal ranking of backends,
globalization policies, or derivative constructions.
